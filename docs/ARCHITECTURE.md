# 系统架构

```text
用户文字 / 商品图片
        |
        v
请求解析与约束抽取
        |
        v
Agent Planner ---------> 工具注册表
        |                    |-- search_products
        |                    |-- check_inventory
        |                    `-- compare_products
        v
可切换检索层
  |-- CPU 词项 + RGB 直方图基线
  |-- Chinese-CLIP 共享图文向量索引
  |-- 词法/稠密候选分数融合
  `-- 价格、类目过滤与稳定排序
        |
        v
基于工具证据生成回答 + 商品ID引用 + 可审计 tool trace
        |
        v
离线评测：检索 / 跨视角 / 工具 / 忠实度 / 延迟 / 端到端
```

当前 Planner 是确定性规则基线。检索层同时提供轻量 CPU 基线、Chinese-CLIP 语义检索和词法/稠密分数融合；模型向量离线生成并由清单校验。规划器未来可替换为 LLM/VLM，但 API、JSON Schema 工具协议和评测接口保持稳定。

## 关键设计决定

1. 先做无 API、无 GPU 的闭环，确保仓库可复现。
2. 价格、库存和对比属于确定性工具，模型只负责规划与解释。
3. 保存工具轨迹，使错误可以归因到检索、参数或生成环节。
4. 多模态能力必须通过查询图与索引图不同的跨视角检索证明，而不是仅凭演示截图或原图自检索。
5. 向量索引清单绑定目录哈希与模型名，避免加载过期或不兼容向量。
6. 回答携带结构化商品引用，评测期望引用和引用是否存在于工具目录。

## 部署边界

- 默认Docker镜像只包含CPU基线和仓库内冒烟商品，不包含模型权重、真实数据或密钥；
- 服务以非root用户运行，并通过 `/health` 接受容器健康检查；
- 中文CLIP生产镜像将在固定模型版本、索引挂载和资源上限后单独提供，避免把753MB权重写入基础镜像；
- GitHub Actions对Python测试和Docker构建设置独立门禁。

## 工具调用安全边界

LLM或规则规划器只能输出 `{name, arguments}`。Dispatcher只接受注册表中的工具名，并使用对应Pydantic模型拒绝缺失、类型错误或额外参数；工具执行结果由业务代码产生，模型不能直接构造价格或库存。未知工具、未知商品和非法参数分别返回明确错误，便于评测与错误归因。
