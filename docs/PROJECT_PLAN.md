# 项目实施计划

## 项目目标

实现一个能够理解文字与商品图片、检索商品知识、调用业务工具并给出可验证推荐依据的电商购物 Agent。项目重点不是简单聊天界面，而是可复现的数据、检索、工具编排和评测闭环。

## 阶段与交付物

| 阶段 | 核心问题 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| M0 工程骨架 | 如何保证可复现 | Python 包、API、测试、CI | 新环境一条命令通过测试 |
| M1 CPU 基线 | 不使用 GPU 能否跑通闭环 | 文本检索、图片轻量特征、工具、评测 | 工具选择和约束满足率可计算 |
| M2 多模态 RAG | 如何实现语义级图文检索 | Chinese-CLIP、持久化精确向量索引、ABO 子集 | 跨视角 Recall@K、MRR 优于 CPU 基线（已完成 100 商品实验） |
| M3 Agent | 如何稳定选择工具和参数 | 规则 planner 基线、JSON Schema tool calling | 工具名称、参数与非法调用均可单独评测（基线已完成） |
| M4 系统评测 | 如何证明有效 | 对照实验、消融、CI、错误分析 | nDCG、置信区间、失败案例和延迟（已完成小规模版本） |
| M5 展示部署 | 如何让面试官快速体验 | 内置 Web UI、FastAPI、Docker、GitHub Actions | 克隆可运行、界面可演示（已完成 CPU 版本） |

## 核心评测

- 检索：Recall@1/5/10、MRR、nDCG@K；
- 图片理解：商品类别及属性 micro/macro F1；
- 工具调用：工具选择准确率、参数 exact match、非法调用率；
- Agent：任务成功率、预算/库存等约束满足率、平均调用步数；
- RAG：回答忠实度、引用命中率；
- 工程：P50/P95 延迟、CPU/GPU 显存、单请求成本。

## 风险控制

- 先固定数据切分和评测集，再更换模型，避免只展示个别成功案例；
- 将检索器、规划器和工具层解耦，便于做消融；
- 商品价格与库存只从工具返回，不允许模型凭空生成；
- 图片和数据必须记录来源与许可证；
- 密钥、权重、索引和大体积输出不进入 Git。
