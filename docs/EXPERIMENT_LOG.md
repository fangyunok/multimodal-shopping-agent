# 实验记录

## 2026-09-06：M0-M1 CPU 基线

### 环境

- Windows，本机 CPU；
- Python 3.11.9；
- 不使用外部模型 API；
- 自建 5 条商品冒烟数据和 4 条端到端评测数据。

### 方法

- 文本：中文单字与英文/数字词项匹配，并使用平滑 IDF；
- 图片：RGB 分通道直方图和平均亮度；
- 融合：同时有图文时文本 0.65、图片 0.35；
- 排序后调用库存工具，过滤无库存结果。

### 结果

- 自动化测试：6 passed；
- 该结果只验证工程闭环，不代表真实多模态语义能力；
- 下一阶段用固定评测集对比中文 CLIP 与该基线。

### 已知局限

- 中文单字检索不能处理语义相似表达；
- 颜色直方图不理解商品类别、款式和局部结构；
- 当前 Planner 仅覆盖检索与对比两类意图；
- 示例集规模很小，不能作为简历最终指标。

## 2026-09-06：图片上传接口

- JSON API 禁止传入服务器本地图片路径，避免任意文件读取风险。

## 2026-09-07：中文 CLIP 真实 CPU 实验

### 配置与可复现性

- 模型：`OFA-Sys/chinese-clip-vit-base-patch16`，通过 ModelScope 镜像下载到本地忽略目录；
- 权重文件 SHA-256：`7B7B583C210C867410BC6BDB8A55FE14EEC62999E0A9EA31FF222DC501F9CFBE`；
- 环境：Windows、Python 3.11、PyTorch 2.10.0+cpu、Transformers 4.57.3、CPU；
- 数据：ABO 100 个商品及 100 张图片，索引维度为 512；
- 文本最长截断到模型的 512 token 上限，图像与文本均分批编码，避免 CPU 内存峰值；
- 新版 Transformers 与旧模型配置的 pooler 不兼容，适配层显式使用首 token 表征再执行模型自带文本投影。

### 结果

| 方法 | Recall@1 | Recall@5 | Recall@10 | MRR |
| --- | ---: | ---: | ---: | ---: |
| CPU 词项基线 | 0.3333 | 0.7500 | 0.8333 | 0.5139 |
| Chinese-CLIP 仅商品文本 | 0.3333 | 0.3333 | 0.4167 | 0.3438 |
| Chinese-CLIP 商品图文等权融合 | 0.3333 | 0.4167 | 0.4167 | 0.3500 |

困难集共有 12 条 test 商品属性查询。CLIP 在 R@1 持平、其余指标落后；文本-only 消融还略低于图文等权结果，表明图片不是主要退化来源，且提供了少量互补信息。主要矛盾是该困难集依赖精确品牌、颜色和材质词，而单个稠密向量不擅长精确词项匹配。该负结果将作为后续“词法召回 + CLIP 语义融合/重排”实验的基线，不包装成模型提升。

标题检索自身和原图检索自身在 12 条 test 数据上均得到 Recall@1/5/10=1.0、MRR=1.0；这只验证真实模型的文本、图片、索引和查询链路完整，不作为泛化指标。

## 2026-09-07：词法与 CLIP 分数融合

实现候选并集上的线性分数融合：文本查询同时使用精确词项分数和 CLIP 语义分数，纯图片查询只使用 CLIP。固定困难集的诊断性权重扫描如下：

| 词法权重 | Recall@1 | Recall@5 | Recall@10 | MRR |
| ---: | ---: | ---: | ---: | ---: |
| 0.50 | 0.4167 | 0.6667 | 0.7500 | 0.5056 |
| 0.65 | 0.3333 | 0.7500 | 0.8333 | 0.4897 |
| 0.80 | 0.3333 | 0.6667 | 0.9167 | 0.5119 |

相较词法基线，0.50 权重的 Recall@1 从 0.3333 提高到 0.4167（相对提升 25%），0.80 权重的 Recall@10 从 0.8333 提高到 0.9167；不存在所有指标同时提高的配置。由于只有 12 条规则生成查询，而且扫描直接使用了该集合，这些数字只用于理解融合行为，不作为无偏最终测试成绩。后续应扩充并人工复核数据，再划分验证集选权重、测试集只报告一次。

### 不确定性与确定性复现

- 评测器新增 nDCG@10 与固定种子的 2,000 次 percentile bootstrap 95% 置信区间；
- CPU 词法基线：nDCG@10 0.5925，MRR 95% CI [0.3125, 0.7292]；
- 词法权重 0.65 的融合检索：nDCG@10 0.5724，MRR 95% CI [0.2802, 0.7119]；
- 修复融合候选使用无序集合造成的并列结果不稳定，加入商品 ID 最终排序键；连续两个独立进程得到完全一致的指标与区间；
- 两种方法区间高度重叠，当前数据不足以支持融合优于基线的统计结论。

公开仓库的 5 条商品数据现在可在没有 `split` 字段时自动生成 5 条 benchmark，用于干净克隆 sanity check；其全 1.0 结果只证明安装、生成、检索和指标链路可运行。

## 2026-09-07：Agent 失败分支与延迟评测

- 公开 Agent 回归集从 6 条扩展到 12 条，加入缺货商品、未知商品 ID、对比参数不足、预算内无结果、自然语言比较和零库存查询；
- 输出非法工具调用率以及 P50/P95 单请求延迟；计时范围为商品目录和模型/索引已加载后的 `agent.run`，不包含进程启动或模型加载；
- 本机 CPU 规则 Agent 在原 6 条集上 P50 约 0.19 ms、P95 约 0.39 ms，非法调用率为 0；这些是轻量确定性基线，不可外推为 CLIP 后端延迟。
- 扩展到 12 条后，Agent 对单商品比较请求曾因 Schema 验证异常直接中断；修复后返回友好提示并记录 `invalid_arguments` 轨迹；
- 扩展集共记录 21 次工具调用尝试，其中 1 次参数被 Schema 拒绝，非法调用率 0.0476；任务成功率、工具选择准确率和参数期望匹配率均为 1.0；
- 本机复测 P50 约 0.07 ms、P95 约 0.41 ms。微秒级差异易受调度影响，面试展示应强调评测口径和数量级，而非小数位。

## 2026-09-07：RAG 引用与回答忠实度

- `AgentResponse` 新增结构化 `citations` 字段，推荐、比较与库存回答同时在人类可读文本中展示 `[商品ID]`；
- 评测数据显式声明 `expected_citations`，避免仅检查“存在任意引用”的弱指标；
- citation hit rate 要求期望商品 ID 全部出现，grounded answer rate 还要求所有实际引用都存在于工具商品目录；
- 12 条公开用例中 8 条包含商品事实，citation hit rate 与 grounded answer rate 均为 1.0；无商品事实的无结果或参数错误回答不进入引用分母；
- 当前答案由确定性模板从工具结果生成，因此该指标是 Agent/RAG 链路回归基线；未来接入生成式 planner/answerer 后需加入价格、库存等逐字段事实一致性判定。

## 2026-09-07：无泄漏跨视角图片检索

从 ABO 的 `other_image_id` 为 100 个索引商品下载其他视角小图：共选择 371 张，已有主图 100 张，新下载 267 张，网络失败 4 张；12 个 test 商品均成功生成一条与索引主图不同的查询图。

| 方法 | Recall@1 | Recall@5 | Recall@10 | MRR | nDCG@10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| RGB 直方图 CPU 基线 | 0.1667 | 0.1667 | 0.2500 | 0.1786 | 0.1944 |
| Chinese-CLIP 图片-only 商品索引 | 0.6667 | 0.6667 | 0.7500 | 0.6806 | 0.6964 |
| Chinese-CLIP 商品图文等权索引 | 0.7500 | 0.7500 | 0.7500 | 0.7500 | 0.7500 |

图文索引相对 RGB 基线的 Recall@1 从 0.1667 提高到 0.7500（绝对 +0.5833，相对 +350%）。其 Recall@1 bootstrap 95% CI 为 [0.50, 1.00]，样本仍小，不能外推到完整电商分布。图片-only 低于图文索引，说明商品文本在共享向量空间提供了互补语义。

剩余 3 个 Top-10 失败全部是外观高度相似的 Solimo 3D 打印手机壳，召回结果也集中为同品牌手机壳；这表明模型能识别大类，但难以区分细粒度图案与适配机型。评测器现会输出 case ID、相关 ID、名次和实际召回 ID，供后续 hard-negative 重排分析。

## 2026-09-07：LLM Planner 数据集与规则基线

- 人工编写 20 条开发集和 100 条锁定测试集，二者查询不重复；测试集覆盖搜索、比较、库存、预算、同义表达、显式意图、不充分信息和对抗输入；
- 测试集锁定后只用于最终对比，不根据其结果修改 prompt；
- Rule Planner 在 100 条锁定集上的 intent accuracy 为 0.75、max-price accuracy 为 0.87、category accuracy 为 0.49、joint accuracy 为 0.36、invalid output rate 为 0；
- 在“字段有明确标注”的子集上 exact joint accuracy 为 0.9524，而 synonym 子集 joint accuracy 为 0，清楚暴露了规则方法的泛化短板；
- 评测器同时记录 P50/P95 延迟和 prompt/completion/total token 数，便于比较 LLM 的效果、延迟与成本；
- `scripts/run_planner_comparison.ps1` 可依次运行 Rule 锁定集、LLM 开发集和 LLM 锁定集。

目前未填写真实 LLM 成绩：本机没有可用的 OpenAI-compatible 推理服务，也尚未获得付费 GPU 授权。该空缺是实验状态的如实记录，不使用模拟结果代替。下一步是在获得接口或 GPU 后，以固定模型、temperature=0 和同一套 100 条锁定数据运行一次对比。
