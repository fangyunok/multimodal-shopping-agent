# 实验记录

## 2026-09-06：M0-M1 CPU 基线

### 环境

- Windows，本机 CPU；
- Python 3.11.9；
- 不使用外部模型 API；
- 自建 5 条商品冒烟数据和 4 条端到端评测数据。

### 方法

- 文本：中文单字与英文/数字词项匹配，并使用平滑 IDF；
- 图片：RGB 分通道直方图和平均亮度；
- 融合：同时有图文时文本 0.65、图片 0.35；
- 排序后调用库存工具，过滤无库存结果。

### 结果

- 自动化测试：6 passed；
- 该结果只验证工程闭环，不代表真实多模态语义能力；
- 下一阶段用固定评测集对比中文 CLIP 与该基线。

### 已知局限

- 中文单字检索不能处理语义相似表达；
- 颜色直方图不理解商品类别、款式和局部结构；
- 当前 Planner 仅覆盖检索与对比两类意图；
- 示例集规模很小，不能作为简历最终指标。

## 2026-09-06：图片上传接口

- 新增 `multipart/form-data` 图片输入；
- 仅允许 JPEG、PNG、WebP，大小不超过 5 MB；
- 对图片内容执行解码校验，并在请求结束后删除临时文件；
- JSON API 禁止传入服务器本地图片路径，避免任意文件读取风险。

## 2026-09-06：中文 CLIP 可切换后端

- 新增共享图文向量空间的编码器协议；
- 接入 `OFA-Sys/chinese-clip-vit-base-patch16` 适配器；
- 商品图文向量与查询图文向量均进行 L2 归一化；
- 用假编码器测试跨模态排序逻辑，CI 不下载大模型；
- 默认仍运行 CPU 轻量基线，CLIP 作为可选依赖启用。

## 2026-09-06：持久化向量索引

- 新增离线商品图文编码与 `vectors.npy` 持久化；
- 索引清单记录目录哈希、编码模型、商品数、向量维度和 UTC 时间；
- 服务可加载已有索引，避免启动时重复编码商品库；
- 目录变化、模型不一致或向量形状异常时拒绝加载。

## 2026-09-06：数据准备管线

- 支持导入 JSONL 和 CSV 商品表；
- 强制记录数据来源与许可证；
- 校验 JPEG、PNG、WebP 图片并按 SHA-256 去重；
- 基于商品 ID 哈希稳定划分 train/validation/test；
- 原始大数据、处理后数据与图片默认不进入 Git。

## 2026-09-06：ABO 数据适配器

- 选择官方 CC BY 4.0 的 Amazon Berkeley Objects 作为真实图文检索数据；
- 只使用约 83 MB 商品 metadata 和约 3 GB 的 256px 图片包；
- 优先提取中文字段，缺失时回退英文；
- 关联主图并映射品牌、颜色、材质、风格等属性；
- 明确 ABO 不用于价格和实时库存评测。

## 2026-09-06：ABO 真实数据冒烟运行

## 2026-09-07：中文 CLIP 真实 CPU 实验

### 配置与可复现性

- 模型：`OFA-Sys/chinese-clip-vit-base-patch16`，通过 ModelScope 镜像下载到本地忽略目录；
- 权重文件 SHA-256：`7B7B583C210C867410BC6BDB8A55FE14EEC62999E0A9EA31FF222DC501F9CFBE`；
- 环境：Windows、Python 3.11、PyTorch 2.10.0+cpu、Transformers 4.57.3、CPU；
- 数据：ABO 100 个商品及 100 张图片，索引维度为 512；
- 文本最长截断到模型的 512 token 上限，图像与文本均分批编码，避免 CPU 内存峰值；
- 新版 Transformers 与旧模型配置的 pooler 不兼容，适配层显式使用首 token 表征再执行模型自带文本投影。

### 结果

| 方法 | Recall@1 | Recall@5 | Recall@10 | MRR |
| --- | ---: | ---: | ---: | ---: |
| CPU 词项基线 | 0.3333 | 0.7500 | 0.8333 | 0.5139 |
| Chinese-CLIP 仅商品文本 | 0.3333 | 0.3333 | 0.4167 | 0.3438 |
| Chinese-CLIP 商品图文等权融合 | 0.3333 | 0.4167 | 0.4167 | 0.3500 |

困难集共有 12 条 test 商品属性查询。CLIP 在 R@1 持平、其余指标落后；文本-only 消融还略低于图文等权结果，表明图片不是主要退化来源，且提供了少量互补信息。主要矛盾是该困难集依赖精确品牌、颜色和材质词，而单个稠密向量不擅长精确词项匹配。该负结果将作为后续“词法召回 + CLIP 语义融合/重排”实验的基线，不包装成模型提升。

标题检索自身和原图检索自身在 12 条 test 数据上均得到 Recall@1/5/10=1.0、MRR=1.0；这只验证真实模型的文本、图片、索引和查询链路完整，不作为泛化指标。

## 2026-09-07：词法与 CLIP 分数融合

实现候选并集上的线性分数融合：文本查询同时使用精确词项分数和 CLIP 语义分数，纯图片查询只使用 CLIP。固定困难集的诊断性权重扫描如下：

| 词法权重 | Recall@1 | Recall@5 | Recall@10 | MRR |
| ---: | ---: | ---: | ---: | ---: |
| 0.50 | 0.4167 | 0.6667 | 0.7500 | 0.5056 |
| 0.65 | 0.3333 | 0.7500 | 0.8333 | 0.4897 |
| 0.80 | 0.3333 | 0.6667 | 0.9167 | 0.5119 |

相较词法基线，0.50 权重的 Recall@1 从 0.3333 提高到 0.4167（相对提升 25%），0.80 权重的 Recall@10 从 0.8333 提高到 0.9167；不存在所有指标同时提高的配置。由于只有 12 条规则生成查询，而且扫描直接使用了该集合，这些数字只用于理解融合行为，不作为无偏最终测试成绩。后续应扩充并人工复核数据，再划分验证集选权重、测试集只报告一次。

### 不确定性与确定性复现

- 评测器新增 nDCG@10 与固定种子的 2,000 次 percentile bootstrap 95% 置信区间；
- CPU 词法基线：nDCG@10 0.5925，MRR 95% CI [0.3125, 0.7292]；
- 词法权重 0.65 的融合检索：nDCG@10 0.5724，MRR 95% CI [0.2802, 0.7119]；
- 修复融合候选使用无序集合造成的并列结果不稳定，加入商品 ID 最终排序键；连续两个独立进程得到完全一致的指标与区间；
- 两种方法区间高度重叠，当前数据不足以支持融合优于基线的统计结论。

公开仓库的 5 条商品数据现在可在没有 `split` 字段时自动生成 5 条 benchmark，用于干净克隆 sanity check；其全 1.0 结果只证明安装、生成、检索和指标链路可运行。
